# 2026-10-08：修复 Nero 真机归位超时与控制权交接

## 问题依据

用户报告网页第三步归位提示 `right_arm: home timed out`，目测左右臂都曾到达初始位置，随后右臂又向下移动。原管理器将归位当作普通服务，仅等待 5 秒，而 Nero 驱动内部允许执行 20 秒。驱动的同步归位回调还会阻塞其单线程执行器，导致归位期间不发布统一关节反馈。管理器失败后恢复 IDLE，存在仍在归位时重新发送旧保持目标的风险。

这是代码中确认存在的问题链；现场那一下移动的具体原因仍需修复后复测确认。

## 修改

- 管理器调用归位服务使用独立的 `home_timeout`（默认 30 秒）；普通服务仍使用 5 秒。归位失败、被打断或控制状态切换失败时进入 ESTOP 并调用各驱动急停，不再无条件返回 IDLE。
- Nero 归位改为异步服务：定时器持续发布实测状态，验证到位后才完成服务；允许反馈检查、命令看门狗与急停继续执行。保留单线程执行器。
- 到位条件为所有关节误差小于 0.05 rad，且实测位置相对稳定参考在 0.002 rad 内保持 0.3 秒，避免刚进入误差范围就打断仍在执行的轨迹。
- 新增 `adapter_config.nero_can.home_timeout` 与 `home_speed_percent` 启动参数，默认 20 秒与 10%，归位速度与原 XNero 的 `init_speed_percent: 10` 一致；完成后恢复 JS 模式和 100% 速度。
- 左右臂共用 HOMING 阶段：先到位的一侧保持，等待另一侧完成；等待有时间上限且要求反馈持续有效。
- 归位开始、完成及退出 HOMING 时建立命令时间戳屏障，拒绝此前积压的命令，保持原关节名、限位和正常命令超时检查。
- 拒绝 SDK 缓存中的陈旧反馈，归位失败日志包含实际关节、目标关节及最大误差。
- XHand 重定向的两路实测反馈订阅改为 best effort，匹配原生驱动的发布 QoS。
- XHand 命令包完整零初始化，包括 SDK 会发送的四个保留字段；SDK 参数错误时打印各关节完整命令参数。未改变既有增益、限位和设备映射。原 `1501030` 是否由保留字段造成，仍需真机复测。

## 验证和部署边界

在部署主机使用隔离 ROS 域、替换 CAN SDK 的真实 ROS 节点和合成手部反馈验证，31 项针对性检查通过。详细命令和日志见 [测试报告](../test_logs/2026-10-08-nero-home/README.md)。

本次未触发真机使能、归位、运动或急停，也未重启用户正在运行的真机进程。同步和编译完成后，用户需要停止旧机器人进程并重新启动，才会加载新代码。实际归位及 XHand 命令执行尚需用户复测。
