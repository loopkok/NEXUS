# 2026-10-08：修复 XHand 真机反馈反复离线

- 将真机 XHand 桥接改为单线程执行。原桥接的短回调在 ROS 2 Humble 多线程执行器中严重饥饿，导致原生 100 Hz 状态转换后仅剩约 1–9 Hz，并产生数秒断流。Wuji 的服务等待仍保留独立执行方式。
- 修复桥接向原生 XHand 驱动发布命令的 QoS：可靠发布、深度 1，匹配厂商可靠订阅；候选命令与反馈继续使用 best effort。
- 原生驱动检查 SDK 读取错误与非有限关节值，错误时不将返回值作为新反馈发布；状态发布改为 best effort、深度 1。保留 SDK 的被动读取模式与 100 Hz 设置。
- 增加 SDK 错误码、状态发布频率、读取/发布/回调耗时，以及桥接接收/转发频率、拒绝原因、关节名/数值/限位、反馈间隔日志。
- 桥接拒绝过期或异常时间戳，保留 0.5 秒反馈时效检查与使能前命令拦截。
- 新增只读双手诊断脚本、ROS/Web 在线判定与命令阻断回归测试、C++ SDK 状态过滤测试。测试使用隔离 ROS 域，合成命令测试的原生话题另行重映射。
- 处理 Humble 在 SIGINT 关闭上下文时可能出现的订阅转换异常；运行期间的 RuntimeError 仍正常报错。

主机对比记录见 [测试报告](../test_logs/2026-10-08-xhand-feedback/README.md)。
