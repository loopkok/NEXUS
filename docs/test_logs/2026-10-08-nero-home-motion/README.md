XHand 桥接与原生反馈在归位阶段约 100 Hz；启动时左手有一次 CRC/约 101 ms 间隔。本次归位失败日志明确列出的是左右臂 J7，未出现手部断流作为归位失败原因。

## 判断与限制

- **现场采样没有显示 J7 向目标明显收敛**，不能仅按“负载导致到位差几度”处理。将 J7 容差改成 0.10 rad，会让这两次未明显收敛的记录通过判定。
- 约 2 秒的进度采样无法排除采样间的短暂运动；日志不是连续运动轨迹。新版本会在每次有效关节反馈时统计运动范围，补足这一限制。
- 停机前有使能且无故障标志，排除了将停机后的失能/抱闸状态误当作失败原因的解释，但不证明电机实际输出了足够力矩，也不排除机械、负载或控制器问题。
- 已有实际 SDK 的内存传输测试确认七个关节目标均编码并提交，J7 为 `0x170`、有符号毫度；原 XNero SDK 同样发送该帧。这不等于控制器接受或执行了该目标。没有证据支持擅自调整帧顺序、自动重发或切换 JS 追赶。
- 两臂先前只读查询均为固件 1.10，`NeroFW.DEFAULT` 与厂商选择表一致。厂商说明旧固件的电机速度反馈无效，电流符号具有版本差异；不能用 `velocity=0` 单独认定电机没动，也不能把电流换算结果当作标定力矩。参考：[厂商固件说明](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/nero/firmware_reference.md)。

**物理根因仍未确认；本次没有宣称修复 J7 真机运动。** 后续应验证 J7 对目标变化的响应，并结合停机前电流、驱动状态和实际运动，区分指令执行与负载/机械问题；无需继续盲目重复整臂归位。

## 本次代码

1. 在每次有效关节反馈时更新归位起始位置、最小/最大位置；诊断逐轴包含位移、观测运动范围、误差减少量。
2. 尚未到位且运动范围不超过 0.002 rad 的关节，列入 `minimal_motion_pending_joints`；这是运动描述，不指定故障原因，也不会提前终止归位。
3. 在原有进度、失败前快照、只读诊断服务中增加七轴 SDK 缓存电流、速度和缓存年龄。未获取、过期、非有限值明确标记；诊断异常不能阻止原有失败停机。
4. 不修改目标、0.05 rad 容差、速度、20 秒预算、发包顺序、运动模式切换或遥操算法。

## 验证与部署

12 项隔离测试全部通过，耗时 14.923 秒，结果见 [isolated_tests.log](isolated_tests.log)。测试使用 ROS 域 186 和 PID 独立实例，在构造驱动前替换 SDK 工厂，不打开物理 CAN。假驱动的长归位用例分别接收 156 / 157 帧，最大间隔 220.2 / 295.1 ms，满足用例的 0.5 秒持续反馈要求；这些数值不是实际硬件遥操延迟测量。

- 复现 J7 固定而前六轴到位，仍必须失败，快照保留 J7 的零运动范围和停止前缓存电流。
- 成功归位即使 SDK 速度反馈一直为零，也按实测关节运动正确统计，不误报关节未动。
- 电流缓存为 NaN 时，诊断记录不可用原因，归位失败仍能停止假电机。
- 只读诊断服务不改变硬件命令计数。
- 原有归位生命周期、超时、反馈、急停、旧命令隔离与 IK、七轴发包检查一并回归。
