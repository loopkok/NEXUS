CRC 的具体来源仍需区分链路、协议解析及 SDK 行为。当前证据不支持直接认定 USB 线或某个波特率是唯一原因。命令与状态的 QoS 在源码中可匹配，日志未出现 QoS 不兼容；掉频已经出现在原生驱动发布端，统一 bridge 收到后基本按相同频率转发。

`SDK_read_errors=0` 不是串口无错误的证明：当前 `read_state(id, false)` 读取 SDK 缓存，CRC 日志来自底层解析/命令链。发布时使用 `now()` 重新打 ROS 时间戳，不能只凭这些时间戳证明硬件测量本身的新鲜度。后续数采验收需要包含硬件反馈有效性，避免把缓存重复发布当作新的实测采样。
